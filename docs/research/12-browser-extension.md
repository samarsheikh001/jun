## 2. Chrome Web Store rules

- **No remote code** (MV3): all logic in the package; no remote scripts, no `eval` of fetched strings, no interpreter of server commands ([policy](https://developer.chrome.com/docs/webstore/program-policies/mv3-requirements)). Calling an LLM API returns data, so it's fine; a fixed action set driven by tool calls is fine; running model-written JS isn't *(inferred)*.
- **Single purpose**, no broad toolbars; injected page toolbars discouraged ([FAQ](https://developer.chrome.com/docs/webstore/program-policies/quality-guidelines-faq)). Purpose: "AI help with the page you're on", UI in the side panel.
- **Limited Use**: only what the purpose needs, browsing data only as a prominent feature, sharing only as needed for it (page text to the person's chosen AI), a public privacy policy ([policy](https://developer.chrome.com/docs/webstore/program-policies/limited-use)). **2026-07 update** (enforced 2026-08-01): "strictly necessary", prominent disclosure, and a ban on extensions that circumvent AI services' protective measures ([blog](https://developer.chrome.com/blog/cws-policy-updates-2026)).
- **Host permissions**: `<all_urls>` at install triggers in-depth review *(unverified, [write-up](https://extensionbooster.net/blog/chrome-extension-host-permission-in-depth-review-warning-fix-guide/))*. Use `activeTab` + `scripting` + optional host permissions asked per site ([activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)).
- **Side panel**: Chrome 114+, per-tab with `setOptions({ tabId })`, `open()` needs the user gesture ([API](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)).
- **CSP**: isolated-world content scripts follow the extension's CSP, not the page's ([docs](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)); `chrome-extension://` frames bypass the page's `frame-src` ([Chromium test](https://chromium.googlesource.com/chromium/src/+/733b05c67da81b70c0cdcb1538bbce1e1afe8681/chrome/browser/extensions/extension_csp_bypass_browsertest.cc)); an `https://` frame from our desk inserted into the page is subject to it *(inferred)*. So no iframes from a Jun domain.

## 3. The person's own AI

- **Sign in with ChatGPT** is now an official OpenAI programme: a limited trial for commercial partners, plan usage "open to all open-source partners" ([quickstart](https://developers.openai.com/siwc/quickstart), [request](https://developers.openai.com/siwc/request-client-id)), scoped to "open-source and locally hosted apps" ([overview](https://developers.openai.com/siwc/token-sharing-open-source)). The open-source flow: PKCE, `client_id=dynamic_agent_client` registration, redirect **only** `http://127.0.0.1:<port>/auth/callback` ([sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)). An extension can't listen on a port and `chrome.identity.launchWebAuthFlow` ends only on `https://<id>.chromiumapp.org/` ([API](https://developer.chrome.com/docs/extensions/reference/api/identity)). Options: catch the failed navigation to the 127.0.0.1 callback with `webNavigation` / `tabs.onUpdated` *(inferred, untested)*, paste the address back (as the deployed desk does), or a native host. Whether a Web Store extension is eligible is open: ask OpenAI. **Never reuse Codex's client id** ([discussion](https://github.com/openai/codex/issues/6403)); that risks OpenAI's terms and the Store's circumvention rule.
- **API keys**: extension pages and the service worker can fetch cross-origin with host permissions; content scripts can't ([docs](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)). Anthropic needs `anthropic-dangerous-direct-browser-access: true` ([Simon Willison](https://simonwillison.net/2024/Aug/23/anthropic-dangerous-direct-browser-access)); Gemini's OpenAI-compatible endpoint has CORS reports from browsers ([forum](https://discuss.ai.google.dev/t/gemini-api-cors-error-with-openai-compatability/58619)), avoided from extension contexts *(inferred)*.
- **Chrome built-in AI** (Gemini Nano Prompt API): stable for extensions since Chrome 138 *(inferred from the status table)*, desktop only, 22 GB disk and > 4 GB VRAM or 16 GB RAM ([docs](https://developer.chrome.com/docs/extensions/ai/prompt-api)). Too small to plan; maybe later for on-device masking or intent.

- **Nanobrowser** (Apache-2.0, ≈ 14.2k ★, v0.3.0 rewrite): WXT 0.21.4, AI SDK 7, one agent loop **in the service worker** (`src/extension/run-manager.ts`: "the worker owns the run; panels are views"), alarm watchdog, Confirm cards reopen after a restart; per-tab panel opened synchronously in the gesture (`src/extension/panel.ts`); keys under their own storage key (`src/store/settings.ts`); optional permissions (`src/ui/manifest-permissions.ts`); page text in marked boundaries in the prompt. ## 5. What it means for Jun

1. **WXT** in a root `extension/` workspace (runtime deps, so not under `packages/`); Preact via `preact/compat` like the widget; minified, page-controller's eval stripped as in `pageControlChunk`.
2. **Loop in the side panel** first (always open while chatting, no worker time limits); the worker opens the panel in the gesture and relays; the content script is **injected on demand** with `chrome.scripting`, isolated world. Move the loop into the worker (Nanobrowser's run manager) only when runs must outlive the panel.
3. **Reuse**: split `web/page-control/index.ts` into a host-neutral `createPageTools(...)` used by both the loader chunk and the extension; `shared/page-control.ts`, `shared/debug.ts` and `pointer.ts` as they are; widget components (steps, Confirm card, composer), not `WidgetApp`. `packages/llm` is text-only, so the loop uses the AI SDK (`streamText` + tools), already a dependency.
4. **Permissions**: `sidePanel`, `activeTab`, `scripting`, `storage`; provider API hosts required; page access optional, asked per site.
5. **Safety**: page text inside marked boundaries and never instructions; click / type / choose behind Confirm (Jun's `allow-always` / `every-time` / `never`); secret fields never read (`PRIVATE_SELECTOR`) even with masking off; payment and passwords always the person's own step; later, a check of each action against the request.
6. **Store**: narrow purpose, privacy policy page, prominent disclosure that page text goes to the chosen provider; no model-written code run.
7. **AI**: API keys first (OpenAI, then Anthropic / Gemini); ChatGPT sign-in only through OpenAI's documented open-source flow after asking about eligibility.
8. **Pitch**: guide first, act second, any AI, open source, no server.
